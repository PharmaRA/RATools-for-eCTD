# Regional metadata import

P6-05 implementation and local Windows acceptance, 2026-11-06. Import now saves
typed regional content, actual node/placement contexts and exact source XML
evidence in the existing application import transaction. The FDA/EU writer work
and regional rule/profile qualification continue in P6-06 through P6-09. P6-02
Formal admission gates remain in force.

## Values, context and diagnostics

EU imports preserve ordered envelopes, identifiers, country/agency/procedure,
submission type/mode/number/unit, applicants, tracking numbers, invented names,
INNs, related sequences and descriptions. US imports preserve application and
submission fields, ordered contacts, typed phones, multiple emails and form
context. Equal business values remain distinct ordered entries. Stable entry IDs
derive from the exact source digest and XML location; missing values are not
replaced with application UUIDs, request sponsors or fixed countries/languages.

Country, language, PI type and form type come from the actual XML ancestors.
Contexts reference actual placement IDs and their bound node, so two leaves of
one document retain different contexts. ICH node contexts bind their original
index evidence. Compatible archival M1 sections without a current node schema
retain an unbound placement context and an explicit diagnostic.

Unknown elements/attributes, unsupported namespaces/versions, incompatible
element parents and unrepresented values produce source-path diagnostics.
Business-incomplete values remain unqualified drafts. Duplicate scalar/container
shapes and unsafe ambiguity reject that sequence before any of its documents,
placements or lifecycle targets become committed import state. The importer
does not claim DTD or regional regulatory qualification from successful parsing.

Imported provenance is generated by the importer as `Imported` / `Unconfirmed`
and binds the actual evidence ID and SHA-256. The existing publishing-metadata
GET exposes the imported regional head and the shared compatibility projection.
Import issues add optional `fieldPath`; raw XML bytes are not returned in the
import response. Reimporting the same application/workspace returns a conflict.

## Original source and atomic persistence

`ImportedRegionalEvidence` preserves exact index/regional bytes, including BOM,
encoding and whitespace, alongside sequence-relative path, SHA-256, metadata ID
and immutable standards snapshot. Individual XML sources are bounded to 8 MiB;
the batch also has an aggregate evidence limit. Evidence readers verify digests
and return defensive byte copies. Existing normalized imported backbones remain
readable; old rows without original evidence return an empty evidence collection.
Reconstructed XML is never labelled as an original source.

The import transaction saves application/sequence, node graph, documents,
placements, archival backbones, regional revision/head/contexts, and original
evidence. Placement rows precede regional context FK checks; original evidence
follows its regional revision. The existing node import advances workspace 0 to
1 once; the regional head binds that resulting revision. Failure after the actual
evidence insert rolls back all imported rows and projections.

Migration `20261106090000_AddRegionalImportEvidence` adds one table with scoped
revision/snapshot FKs, a unique application/sequence/path, byte budget, exact
snapshot and SHA-256 insertion guards, and immutable update/delete/truncate
guards. Downgrade refuses evidence loss. A separate read-only review approved the
migration before application; apply, repeat apply and model parity passed.
