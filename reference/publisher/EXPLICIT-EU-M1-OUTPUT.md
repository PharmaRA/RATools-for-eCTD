# Explicit EU M1 output

P6-07 implementation scope, 2026-11-06. EU output consumes captured typed
regional metadata and actual placement contexts. The technical baseline is the
official EU M1 3.1.1 implementation package, whose XML DTD version attribute is
`3.1`. The selected local trial matrix covers national DE/FR/BE envelopes and
German/French PI contexts. It does not activate a regional profile or qualify
every procedure/country/language represented in the DTD.

## Explicit values and contexts

All ordered envelopes and their identifiers, applicants, submission fields,
tracking numbers, invented names, INNs, related sequences and descriptions enter
output as supplied. Equal values remain distinct list entries. The package uses
its actual sequence number, and related references follow the previously pinned
business selection: initial/reformat refers to current sequence; other units
refer to an earlier existing sequence in the same application.

Countries, PI language and PI type come from the actual placement context, then
its exact node context. A present context with null fields expresses clearing;
it cannot borrow values from another placement or an envelope. Two leaves of
one file can produce separate country/PI wrappers. Leaf IDs, ordering, hrefs and
lifecycle references remain associated with the actual placements.

The old internal-UUID identifier, application-number product/tracking values,
fixed `ema`, `EU-EMA`, `centralised`, `en`, `combined`, and automatic related
sequence projections are removed from production package construction. Missing
typed metadata or required context produces a specific diagnostic. Old shared
metadata remains readable, and an explicitly constructed legacy flat EU object
can be used by compatibility fixtures; it is never generated from missing values
or selected as a fallback for an incomplete typed regional head.

The DTD requires a cover section and country wrapper. The current node schema
contains a generic m1 root and cannot represent an independent empty m1.0 cover
context. Current typed output therefore requires a real cover placement with
an explicit country. A generic m1 node cannot stand in for it, and the writer
does not infer cover country from the first envelope. Empty-cover authoring
remains outside this selected scope.

## Binding and qualification

Package construction retains P6-06's immutable regional revision and exact
standards snapshot under the workspace lock. The actual application's history
establishes related-sequence existence. Writers consume captured content without
reading mutable stores. Ordinary generation and release capture retain the
same profile binding; the manifest-bound `regional-metadata.json` attachment
preserves the original revision outside the regulatory delivery payload.

## Verification record

The independent parent input is hand-written EU XML with two national envelopes,
two applicants, three ordered DE tracking values including a repeat, multiple
names/INNs, a Belgian cover and two PI leaves sharing one source file. It is not
generated by the writer. The baseline HTTP and PostgreSQL tests both failed
because output replaced `de/fr` envelopes with one fixed `ema` envelope.

The final input expands each PI wrapper to two leaves, including a separate HTTP
case where both original wrappers have identical country/language/type. Initial
local sibling SortOrder values interleaved the leaves. Package construction now
uses each archived backbone's actual parent-wrapper identity before local sort,
then original traversal order. Editing context values cannot change the source
wrapper identity. Missing or ambiguous archive evidence produces an explicit
diagnostic. The bounded reader never replays unknown source XML into output.

Final analyzed layer is
`.artifacts/current-head-review-20261104/p607-backend-stage5/`. Four layers and
`p607-round2-green.log` passed 51 direct cases. `p607-parent-final.log` passed
seven independent cases: actual HTTP editing with different and identical PI
contexts, real PostgreSQL new-connection construction, DTD/output/full reimport,
regional capture evidence, and HTTP missing-head refusal, plus the direct import
parser/HTTP cases. Counts overlap. Stage2 also passed 38 US/capture regressions
and 14 safe legacy imports; stage3 passed seven safe old readiness/publish cases.

Missing EU input now becomes a structured Blocked readiness finding and a
backbone HTTP 400 with code, fieldPath and message. Actual HTTP first reproduced
500, then passed after repair. OpenAPI changes only the existing backbone
endpoint's 400 response, without schema changes; generated types, TypeScript and
ESLint checks passed.

The independent libxml2 comparison in
`.artifacts/p607-independent/libxml2-comparison.json` accepted all three actual
outputs and rejected six country/PI-type mutations. It records the exact DTD and
output hashes and tool versions; it is a structural comparison, not a regional
business validator. Read-only task review is required before commit.

Existing cleanup-owning fixtures are only executed through scoped retained or
recycle-bin adapters. This is local Windows evidence, without a whole repository,
